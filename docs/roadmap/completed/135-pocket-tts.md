# ROADMAP-135 — Локальный Pocket TTS с выбором модели

## Цель

Добавить в TTSBard локальный синтез на CPU. Первый русский профиль —
Shtorm v2 Fast с клонированием голоса по короткой записи. Первый английский
профиль — полноразмерная модель Kyutai English с готовым голосом Alba. Обе модели могут быть установлены
одновременно, пользователь выбирает активную в разделе TTS.

## Хранилище

Использовать существующий каталог `models/pocket`. Как у Piper, сканировать
сначала рабочий каталог процесса, затем эффективный корень «Данные программы»
по [ROADMAP-117](../completed/117-app-storage-split.md). По умолчанию это
`%LOCALAPPDATA%\ttsbard\models\pocket`. Каждому набору — свой подкаталог
со стабильным ID, конфигом и локальными файлами модели.

- `shtorm-ru-v2-fast` — конфиг, токенизатор и исходный safetensors, проверенный
  офлайн на русском. Сохранить происхождение и атрибуцию CC BY 4.0.
- `kyutai-en-18m-2026-10` — официальный английский набор 18,2M для
  синтеза с готовым голосом. Английское клонирование зависит от варианта весов.
- `pocket-en` — уже имеющийся сторонний ONNX-экспорт с ограничением на
  коммерческое использование. Сохранить как локальный исследовательский набор.

## Что уже проверено

Оба исходных набора размещены в общем хранилище. Pocket TTS 4.0.1 на CPU
прошёл офлайн-проверку RU → EN → RU с WAV-референсом для Shtorm и локальным
состоянием голоса Alba для Kyutai. В конфигурациях пути локальные, в прототипе
они разрешаются от папки модели. Для английского набора использованы
официальные веса для готовых голосов. В карточке для этого набора следует
предлагать только готовые голоса.


Адаптированный экспортёр PocketTTS.cpp собрал пять графов Shtorm v2 Fast
и полноразмерной Kyutai English. Выбран общий нативный путь Rust + ONNX
Runtime, Python используется для экспорта и эталонных прогонов. Для Kyutai
используется готовое состояние Alba. Компактный набор Kyutai 18,2M остаётся
экспериментальным, его sampler drifting и проекция z_proj требуют отдельной
поддержки.

Сквозной тест ONNX Runtime CPU с четырьмя потоками воспроизвёл обе модели
до EOS. В INT8 получены WAV 3,44 с (Shtorm, голос из WAV) и 2,08 с (Kyutai,
Alba). Генерация после подготовки модели, голоса и текста заняла около
0,57 и 0,36 с соответственно. FP32 также дошёл до EOS. Результаты по
длительности отличаются от эталона PyTorch, совпадение авторегрессионного
шага и качество речи на слух ещё требуют проверки. Логи, скрипт
`onnx-smoke.py` и аудио находятся в `.work/ai/pocket-tts-smoke/`.

Дополнительно проверен двуязычный синтез Pravega Pocket TTS по одному
пятисекундному английскому референсу Nataly.[^pravega-ru]

## Этапы

1. Проверить единый рантайм CPU на Shtorm RU и Kyutai EN. Эталон — Pocket TTS
   Python, который уже синтезировал русский из локальных весов. Для поставки
   проверить ONNX-экспорт обоих вариантов и сопоставить звук, задержку первого
   фрагмента, RTF и память с эталоном. Выбор рантайма для поставки согласовать
   после проверки.
2. Определить формат дескриптора и обнаружение моделей. Минимальные поля —
   ID, название, язык, формат и версия набора, пути к локальным ассетам и
   доступные режимы голоса. Проверять комплектность при сканировании. Хранить
   несколько моделей на диске и загружать выбранную по запросу. Запросы в
   очереди должны сохранять модель и голос, выбранные в момент отправки.
3. Подключить провайдер к очереди синтеза, предпрослушиванию и отмене.
   Для Shtorm задействовать существующий RUAccent и проверить передачу
   ударений U+0301 и разбиение длинного текста. Для английской модели
   применять английскую подготовку текста.
4. Добавить отдельную карточку «Pocket TTS» рядом с Piper в существующем
   разделе TTS. В карточке показать модель и язык, выбор готового голоса
   или аудиореференса по возможностям модели и понятное
   состояние при отсутствии файлов. Сохранять выбор модели между запусками
   и настройки голоса для каждой модели. При реализации обновить
   [карту UI](../../development/ui-map.md).

## Исходный проект карточки

Список показывает название, язык и готовность каждой модели. Для Shtorm
поле «Референс голоса» позволяет выбрать WAV длительностью до 12 секунд.
После проверки карточка показывает имя файла, его длительность и кнопки
воспроизведения, остановки и замены. Если файл исчез, карточка предлагает
выбрать его снова.

В исходном профиле Kyutai English вместо референса отображался готовый голос Alba.
Переключение обратно на Shtorm восстанавливает выбранный ранее WAV.

## Проверка результата

- RU и EN одновременно видны в карточке. Последовательность RU → EN → RU
  работает офлайн на CPU. Выбор восстанавливается после перезапуска.
- Shtorm озвучивает новый русский текст по короткому WAV-референсу.
  Kyutai озвучивает английский текст с поддерживаемым голосом.
- Повреждённый набор или недоступный референс дают понятную ошибку. Другие
  модели и провайдеры доступны. Повторное сканирование подхватывает новый набор.
- Проверить карточку в обеих темах, на RU и EN интерфейсе, с пустым каталогом,
  одной моделью и несколькими моделями. Путь к временному отчёту добавить
  в задачу реализации.

## Outcome

Добавлены локальный провайдер Pocket TTS на CPU через Rust и ONNX Runtime
и карточка выбора модели и голоса. Модели обнаруживаются на диске, а выбор
голоса хранится для каждой модели. Карточка поддерживает готовые голоса
и WAV-референсы по возможностям пакета. Для WAV действует предел 12 секунд,
интерфейс показывает длительность. В текущем каталоге доступны Shtorm RU
v2 Fast и Slow и Kyutai English с WAV-клонированием. Alba относится к
историческому профилю с готовым голосом, использованному в ранних проверках.

Нативный ONNX smoke прошёл RU → EN → RU, включая восстановление после
отсутствующего референса и отмены, на наборах Shtorm Fast и Kyutai English
Full. Для исправленного среза ресемплера добавлен тест сохранения тона
9 кГц при преобразовании 44,1 → 24 кГц. Полная ручная
матрица карточки и оценка качества голоса на слух остаются открытыми.
Измерения F0 и спектра описаны в [исследовании Pocket TTS](../../research/20-pocket-tts-voice-cloning-pitch-and-spectrum.md).
